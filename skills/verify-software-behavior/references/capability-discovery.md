# 测试能力发现

修改测试前，先建立有证据支持的能力清单。

## 检查范围

- 包管理、项目构建文件和锁文件。
- 测试配置、初始化文件和环境配置。
- 现有测试目录、命名方式、夹具、辅助函数和页面对象。
- CI 工作流与项目文档中记录的开发命令。
- 受影响模块附近的测试，以及最近的相关改动。
- 运行前提：浏览器、数据库、服务、凭据、测试数据和环境变量。

## 记录内容

对每项发现的测试能力记录：

- 框架名称和测试层级；
- 0 到 1 的置信度；
- 具体的证据文件路径；
- 已知命令及其来源；
- 相关测试所在位置；
- 所需运行环境和尚未解决的前置条件。

## 策略选择

- `use_existing`：存在强证据，并且相关测试路径可以运行。
- `static_checks_only`：不存在合适自动化方案或自动化成本不成比例，但项目具有可执行的静态检查。
- `manual_verification`：行为依赖当前无法获得的环境或必须由人工观察。
- `needs_confirmation`：存在多种合理方案，或仍需用户决定重要的环境变更。

不得仅凭编程语言或 UI 框架推断测试框架。未经用户明确同意，不得安装或初始化新的测试体系。
